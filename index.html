How it works

Three parts, one idea: nobody defends alone.

Measured, not claimed. Every result says which model and which agent harness it ran against, at which versions, how many runs it took and the interval around the number. They collect in the attack matrix, generated from the data and never written by hand.

01

The registry

Every known attack on AI agents, with a stable ID, a mapping to MITRE ATLAS and OWASP, a harmless test that proves it, a detection that stops it, and the results of running it against named models and harnesses.

02

The sensor

A checkpoint between your agents and the tools they use. It enforces the registry's detections, works offline, and never takes your agent down if it fails.

03

The network

A member's sensor shares anonymized sightings, previewed before anything leaves the machine, and pulls verified rule updates back, so a detection caught at one organization reaches every sensor that updates.

Contribute

Every pattern you add protects everyone who runs the protocol.

Season 1 runs October 5 to October 29, 2026. PROGRAM.md is the one page that says what we are doing, what you can pick up without asking, and what ships at the end: protocol v0.1 and the group's first paper. Live progress is in docs/STATUS.md, generated from the repository so nobody has to be asked.

The most useful thing you can contribute is a harness target. A target is two short methods that let the scan drive an agent you already use, and every one of them turns a pattern nobody has measured on your stack into a row with a rate and an interval. Three exist: Claude Code, Gemini CLI and Codex CLI. Cursor, Ollama and a custom framework like LangGraph are written up and unclaimed in TEST_YOUR_AGENT.md, which also shows how to scan your own agent without writing anything at all.

Everyone here is a contributor. Fork the repository, pick an issue, open a pull request. The machine checks everything first: format, tests, that the rules still catch attacks and still leave ordinary work alone, and that every pattern maps to MITRE ATLAS. Then a reviewer approves and a maintainer merges. Your name, and your organization if you opt in, are credited automatically, in the order people contributed.

How it goes

  1. Pick an issue and comment to claim it.
  2. Fork, branch, and run python3 check.py new-pattern "Title" for a new pattern.
  3. Run python3 check.py, commit with git commit -s, open a pull request.
  4. Automatic checks run and a track label is applied for you.
  5. A maintainer reviews and merges, and the credit list updates itself. There are no reviewers yet, so that approval is a maintainer's today. How someone becomes one.

Three roles

ContributorFork, open pull requests, comment, review. Where everyone starts.
ReviewerBinding approval in an area, after about five good merged pull requests.
MaintainerMerges, cuts releases, promotes patterns. Earned through sustained reviewing.
Start here A first contribution in about fifteen minutes, from a clone to an open pull request. Pick a track Patterns, scanner, sensor, coverage or research. Each one has issues waiting. How decisions are made The three roles in full, how proposals are decided, and who holds the keys. The rules Sign-off, what the automatic checks enforce, and how a change gets in. For maintainers Reviewing, promoting a pattern, adding a reviewer, and the weekly meeting. Report an attack privately Seen something live? Report it privately. We follow coordinated disclosure.
